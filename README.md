# market-data-service

A small FastAPI service that:

- **Proxies ETF constituents** (SPY, QQQ, IWM) from multiple data providers
  (SSGA, iShares) behind a single, provider-agnostic REST endpoint.
- **Caches market data** (OHLCV bars) from Polygon.io on local disk
  (parquet) with a configurable cache horizon so repeated requests don't
  re-hit the upstream API. Prices are stored **raw**; splits and cash
  dividends are kept alongside them and the adjusted view is rebuilt on
  every read, so stored numbers never change.
- **Serves today's bar live** from the [Longbridge OpenAPI](https://open.longbridge.com/)
  QuoteContext — the bar is never persisted because it may still be
  forming.

## Requirements

- Python 3.12+
- [uv](https://docs.astral.sh/uv/) (manages the venv + dependencies)
- (For Polygon-backed endpoints) a Polygon.io API key
- A Longbridge account with OpenAPI credentials for the live bar endpoint

## Setup

```bash
# 1. Install dependencies into .venv
uv sync

# 2. Copy and edit the env file
cp .env.example .env
# then fill in POLYGON_API_KEY and LONGBRIDGE_* credentials
```

## Run

### Option A — Local Python with uv

```bash
uv run python -m app.main
# or
uv run uvicorn app.main:app --host 0.0.0.0 --port 8001
```

The app talks to Longbridge over the public internet; nothing else to
start. ``LONGBRIDGE_REGION`` (``hk`` / ``cn``) is optional and only
needed if the SDK's auto-pick is wrong for your location.

### Option B — Docker Compose (recommended)

Single container: `python:3.12-slim` with the Longbridge SDK
installed and the app layered on top; uvicorn runs as a non-root
user.

```bash
# 1. Fill in the Longbridge + Polygon credentials
cp .env.example .env
$EDITOR .env   # set LONGBRIDGE_APP_KEY, LONGBRIDGE_APP_SECRET,
               # LONGBRIDGE_ACCESS_TOKEN, POLYGON_API_KEY

# 2. Launch everything
docker compose up -d --build

# 3. Tail logs
docker compose logs -f market-data
```

The app is exposed on `localhost:3556` (host port `APP_PORT`, default
`3556`).

## Configuration

All settings come from environment variables (or a `.env` file via
`pydantic-settings`):

| Variable | Default | Purpose |
| --- | --- | --- |
| `DATA_DIR` | `./data` | Root for parquet cache (`market/`, `corporate_actions/`, `constituents/`) |
| `POLYGON_API_KEY` | _empty_ | Polygon.io API key |
| `POLYGON_BASE_URL` | `https://api.polygon.io` | Override Polygon base URL (commented in `.env.example`) |
| `LONGBRIDGE_APP_KEY` | _empty_ | Longbridge OpenAPI app key |
| `LONGBRIDGE_APP_SECRET` | _empty_ | Longbridge OpenAPI app secret |
| `LONGBRIDGE_ACCESS_TOKEN` | _empty_ | Longbridge OpenAPI legacy access token |
| `LONGBRIDGE_TIMEOUT_SECONDS` | `10` | Request timeout for the Longbridge client |
| `LONGBRIDGE_REGION` | _(auto)_ | `hk` or `cn` if the SDK picks the wrong endpoint |
| `LONGBRIDGE_REGION_SUFFIX` | `.US` | Suffix appended to bare tickers (e.g. `AAPL` → `AAPL.US`) |
| `APP_PORT` | `3556` | Host port the FastAPI app listens on |

All date / time-of-day logic is anchored on **America/New_York**
(`zoneinfo.ZoneInfo("America/New_York")`). Bar dates, the Longbridge
cache key, and the "today" check for backfill filtering all reason
in ET. See [`app/config/settings.py`](app/config/settings.py) for the
`ny_now`, `ny_from_ts`, and `ny_midnight_ts` helpers.

## API

The full OpenAPI doc is generated by FastAPI and is available at
`/docs` and `/redoc` once the server is running.

### `GET /health`

Liveness probe.

```bash
curl http://localhost:3556/health
# {"status":"ok"}
```

### `GET /constituents?etf={ETF}&date={YYYY-MM-DD}`

Returns the holding tickers of a supported ETF for a specific snapshot
date. Snapshots are stored on disk as one parquet file per ticker under
`constituents_dir` (default `./data/constituents/`) and refreshed by
`APScheduler` at 8:30 AM US/Eastern every day. If no snapshot exists
for the requested date, returns **404**.

**Parquet schema** (one row per holding per snapshot date):

| Column | Type | Notes |
| --- | --- | --- |
| `date` | `date32` | Snapshot date |
| `ticker` | `string` | The constituent's ticker |

The ETF ticker itself is not stored as a column — it's the filename
(`SPY.parquet`, `QQQ.parquet`, `IWM.parquet`).

| Symbol | Provider | Source |
| --- | --- | --- |
| `SPY` | SSGA | `holdings-daily-us-en-spy.xlsx` |
| `QQQ` | iShares | iShares Nasdaq-100 ETF holdings CSV |
| `IWM` | iShares | iShares Russell 2000 ETF holdings CSV |

```bash
curl 'http://localhost:3556/constituents?etf=SPY&date=2026-08-12'
```

```json
{
  "symbol": "SPY",
  "date": "2026-08-12",
  "source": "parquet",
  "constituents": ["NVDA", "AAPL", "MSFT", "..."]
}
```

Constituents snapshots are refreshed on a schedule by the in-process
job in [`app/services/constituents_scheduler.py`](app/services/constituents_scheduler.py)
(daily 8:30 AM America/New_York); there is no public refresh endpoint.

### `GET /market-data/{ticker}?from={YYYY-MM-DD}&to={YYYY-MM-DD}`

Returns **daily** OHLCV bars for a ticker. Historical bars
(`from..today-1`) are served from the local disk cache (parquet),
backfilled from Polygon.io on miss. **Today's bar** is fetched live
from Longbridge via `LongbridgeClient` and is **never persisted** —
it may still be forming.

Prices are stored **raw** (Polygon `adjusted=false`) and adjusted for
splits and cash dividends at read time, anchored at the last bar of the
requested window. See [Price adjustment](#price-adjustment).

| Query param | Type | Default | Notes |
| --- | --- | --- | --- |
| `from` | `YYYY-MM-DD` | required | Start date (inclusive) |
| `to` | `YYYY-MM-DD` | today (NY) | End date (inclusive) |

Each bar in the response is tagged with `source`:

- `"cache"` — historical bar from the local parquet cache.
- `"longbridge"` — today's bar from Longbridge.

**Quick example — AAPL over the last ~10 trading days:**

```bash
curl 'http://localhost:3556/market-data/AAPL?from=2026-08-10'
```


**Long-range example — full July through the live session:**

```bash
curl 'http://localhost:3556/market-data/AAPL?from=2026-07-01&to=2026-08-01'
```

**Notes:**

- A 502 response with body `Longbridge upstream error: ...` means the
  Longbridge QuoteContext call failed (e.g. no quote permission, rate
  limit hit, network error). Historical bars from the cache are
  unaffected; you'll get them but the response for today's bar will
  be missing.
- `backfilled_bars` reports how many new bars were persisted to the
  cache during this request. Subsequent requests for the same range
  will not trigger backfill.
- "Today" is the **America/New_York** calendar date. At 00:00 UTC the
  US market is only 8 PM old, so the service still treats the prior
  US session as "today".

## Price adjustment

Two stores are kept side by side:

- `data/market/` — raw OHLCV bars, one parquet file per ticker per year.
- `data/corporate_actions/` — one parquet file per ticker holding split
  (`split_from`, `split_to`) and cash-dividend records.

Neither store is rewritten when an action is discovered: reconciliation
only *adds or replaces* individual records, so a partial upstream
response can never destroy cached history. The adjusted view is rebuilt
on each request:

- **Splits** scale prices by `split_from / split_to` and volume by the
  inverse, for every bar strictly before the execution date.
- **Cash dividends** scale prices (not volume) by `1 - D / P_prev`, for
  every bar strictly before the ex-dividend date. `D` is Polygon's
  `split_adjusted_cash_amount`, and only `distribution_type == "CD"`
  rows are used.

The series is anchored at the last bar of the requested window, so an
action dated after `to` does not rescale the response and the same raw
bars plus action records always produce the same numbers.

A weekly in-process job
([`reconcile_scheduler.py`](app/services/reconcile_scheduler.py)) runs
every Saturday at 12:00 PM America/New_York and, per cached ticker,
merges newly published actions and fills any trading days missing after
the newest cached bar. `backfill_yesterday` also refreshes the trailing
30 days of actions on each normal backfill.

`data/market/.price_basis` records the basis version; the first start
after an upgrade from split-adjusted storage wipes the old cache once.

## Adding a new ETF

1. If the provider is new, add a parser under
   `app/services/parsers/<provider>.py` exposing
   `parse(content: bytes) -> list[dict]`. Each parser must return
   `{"ticker", "name", "weight}` dicts.
2. Register the parser in `PROVIDER_PARSERS` in
   [`app/services/constituents_fetcher.py`](app/services/constituents_fetcher.py).
3. Add a registry entry to `ETF_REGISTRY` with `provider` and `link`.

No other code changes are needed — the service auto-derives its
`SUPPORTED_SYMBOLS` set from the registry.
